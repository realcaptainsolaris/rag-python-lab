Each observation contains the fields in the table below. The schema describes the request body, not an export column order. Keep the field name and its meaning together when mapping a source record. A database column named temperature can supply a measurement named outlet-temperature, but its value still needs an explicit unit.

The value field must be a finite JSON number. Strings that look numeric are not converted implicitly, and nonfinite floating-point values cannot be represented as valid measurement values. Validate the sender payload before placing it on a retry queue.

Units and series identity

Changing the unit requires new measurement name required. A series whose first records use Celsius and whose later records use Fahrenheit cannot be safely aggregated without an explicit conversion. Orbit does not infer a conversion from the display label.

If a device firmware upgrade changes units, introduce a new measurement name and keep the conversion in the integration layer. Record the cutover time so existing dashboards can be updated. Resending the earlier samples with a new label is a data migration and should not be mixed with ordinary ingestion retries.

Batch acceptance

The batch endpoint is /api/v3/measurements/batch and accepts at most 200 measurements per request. The required field list is device_id, timestamp, name, value, unit. A batch response reports acceptance per item. Persist the outcome of each item instead of assuming that one HTTP success means every item was valid.

If only a subset failed, repair and resend that subset. Reconstructing an entire batch from a changing input file can create a different set of observations on the second attempt. Keep the source offset and the original item identity with the batch result.

# Rate budget

## Shared workspace budget

Orbit 3.0 allows 1000 requests per minute per workspace. The window is a fixed UTC calendar minute. Separate API keys in one workspace do not receive independent budgets. A dashboard reader and a bulk sender can therefore consume the same allowance.

Before increasing sender concurrency, inventory all callers using the workspace. A single process can appear well below the limit while the combined traffic is excessive. Include polling, retries and administrative calls in the traffic record. Key rotation does not reset the workspace budget.

## RATE-201 response

RATE-201 means workspace request budget exhausted. The rejected request has not gained capacity merely because the caller retries with another token. Back off and coordinate the shared senders. Avoid synchronizing every agent at the top of the next minute; a simultaneous burst can immediately exhaust the new window.

A rate error and an invalid scope are separate conditions. An application should not renew credentials as its default response to RATE-201. Collect the request identifier and workspace without recording token contents.

## Plan for older deployments

Orbit 2.4 has a budget of 500 requests per minute; Orbit 1.8 has 200. A fleet that shares client configuration across generations must use the correct contract for each target.

Use batching when the sender has many small observations. Page size changes affect read traversal; batch size affects write requests. Neither changes the published request budget. When estimating throughput, distinguish observations per request from requests per minute and allow headroom for operational traffic.

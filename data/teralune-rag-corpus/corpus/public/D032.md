# Orbit 2 release notes

## Orbit 2.4 release

Orbit 2.4 was released on 2024-06-18. The API prefix is /api/v2 and the OAuth access-token lifetime is 120 minutes. This release introduces the scoped API-key model for integrations moving from the workspace-wide keys used in 1.8.

Review each integration's read and write needs during that migration. Replacing one broad credential with a restricted reader can make initial connectivity tests pass while stopping observation ingestion. Keep the scope assignment in the rollout record so a later operator can distinguish a deliberate restriction from an accidental omission.

## Capacity and notification changes

The request budget is 500 per minute and the provisioning retention default is 30 days. The measurement event name is measurement.accepted. The retry deadline is 24 hours.

A receiver that still subscribes only to the 1.8 notification name requires an explicit subscription change. The acceptance of an API request does not prove that the receiver subscription was migrated. Record the notification name alongside the client prefix during deployment.

## Connector compatibility

The integration connector for this generation is orbit-push. Keep its configuration with the deployment until the later connector migration is complete. A renamed binary can retain an older configuration format, so package names alone are not a reliable compatibility record.

Archive the previous deployment instructions when completing a migration. Historical release notes describe the released contract and should not be edited to resemble a later generation. Use the later migration guide to determine what changed.

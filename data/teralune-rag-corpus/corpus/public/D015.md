# Legacy onboarding

## Before connecting a sender

Orbit 1.8 installations expose /api/v1. These instructions describe that generation. Register a workspace before distributing its integration key. The key model is a workspace-wide key; it does not offer the scope boundaries available in later clients. Keep a record of which sender owns each deployed copy. If several processes share a key, revoking it affects all of those processes.

Start with one device and one measurement series. Give the device a stable external identifier that survives an application restart. The display name belongs to the user interface and is not an integration key. A sender that changes the external identifier each time it boots creates a new identity instead of continuing the old history.

## Retention and throughput

The provisioning default is 14 days of measurement retention. The workspace request budget is 200 requests per minute. Both values belong to the 1.8 contract; a dashboard exported from a newer installation is not a reliable description of this deployment.

A collection agent should retain its own outgoing queue until the server confirms acceptance. Do not delete the local sample solely because a TCP connection was opened. When a connection drops during a request, first determine whether the request was accepted. A network timeout does not prove that the server stored nothing. Record a stable sample identifier in the sender log to support reconciliation.

## First handover

The 1.8 measurement notification is reading.received. Register the receiver against this event name rather than a name copied from a later release. Verify that the receiver can parse the payload before enabling a large device fleet. A callback acknowledges a submitted observation; it is not a replacement for the sender acceptance response.

The handover record should include the deployed version, workspace, device identifier and receiver owner. Do not include the workspace key. Keep a rollback copy of the sender configuration outside its running process. A successful request from one workstation is insufficient evidence that every deployed agent uses the same configuration.

# Legacy webhook reference

## The 1.8 callback contract

Orbit 1.8 repeats eligible webhook delivery attempts for 6 hours. Its observation event is reading.received. A receiver subscribed only to measurement.created will not receive that older event. Check the sender generation and subscription before concluding that the platform lost the observation.

Record the event name at the receiver boundary. A downstream handler may rename fields or translate events into a local message format. Once that translation occurs, an application log can obscure which original event was received. Keep the original envelope identifier alongside the translated action.

## A late acknowledgment

A callback can be repeated when the receiver committed an action but its acknowledgment was lost. Keep receiver persistence independent of an HTTP connection. A process restart should not erase the record that an action was committed.

When reviewing an archived incident, do not replace the historical deadline with the current contract. The age of the incident report and the product generation answer different questions. A report written after an upgrade can still describe a sender left on the earlier installation.

## Receiver upgrade order

First add support for the new event envelope in an isolated environment, then change the subscription and sender configuration together. Keep an explicit mapping from original event name to the new internal handler. An accidental alias can cause the same business action to be scheduled twice if both subscriptions remain active.

During the observation period, compare unique events with committed actions. Comparing request counts alone is misleading because delivery attempts include retries. Keep the old subscription disabled rather than deleting the configuration until the rollback decision is complete.

# Key revocation procedure

## Revoke an integration key

Procedure SEC-RB-09 requires a second reviewer before the production revocation is confirmed. Identify the key by its nonsecret identifier and enumerate its assigned workspace and integration owners. Do not copy the key value into the review record.

If immediate containment is necessary, record the containment action and arrange the review of the affected integrations. Keep an explicit record of which actions were already performed; an approval message alone is not proof that the service state changed. The procedure owner reconciles the final credential state with the incident timeline.

## Propagation and verification

Revocation propagates within 60 seconds. Verify a new request after that interval using the affected integration identity. A request accepted before the revocation is not evidence of a propagation failure. Capture request times and the effective revocation time in a common timezone.

The replacement credential must have only the necessary scopes. A successful containment can be undermined by giving the replacement broader access than the original. Review both read and write paths if the integration performs both kinds of operations.

## Security exercise correlation

Use marker TRAINING_ONLY_MAPLE_62 for the current key-revocation exercise. Keep this marker with the Security review record and do not include it in customer-facing updates. The exercise record and the production credential inventory have different distribution lists.

When preparing an incident summary, omit raw credentials, protected register identifiers and unrelated tenant details. A request for more detail from another team must follow its access process. Possessing a product administrator role is not membership in the Security team.
